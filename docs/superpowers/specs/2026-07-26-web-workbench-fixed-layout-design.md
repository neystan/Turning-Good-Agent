# Web Workbench Fixed Layout Design

状态：已确认，待实施。

## 目标

在不改变 Runtime、Session、Memory、Tool、MCP、REST、WebSocket 与 JSON/JSONL 边界的前提下，完成 Web 工作台的第三轮布局与交互精修：检查器打开时不遮挡、不挤压、不移动任何已可见聊天内容；权限、活动、审批和 Composer 使用更柔和的大圆角控制面语言。

Reading this as: 本机个人 Agent 工作台，面向高频任务执行用户，采用克制、精密且具软硬件控制面质感的石墨灰对话界面。

| 参数 | 值 |
| --- | --- |
| `DESIGN_VARIANCE` | 3 |
| `MOTION_INTENSITY` | 2 |
| `VISUAL_DENSITY` | 7 |

## 工作区与检查器

桌面端保留左侧会话栏和主工作区。关闭检查器时，主工作区只有一个内容列，消息列与 Composer 在去除左侧会话栏后的全部可用区域内居中。打开检查器时，主工作区内部 Grid 增加右侧检查器列；顶部栏仍跨越整个工作区，主会话容器左边界不动、右边界收缩，消息列与 Composer 在收缩后的可用区域内重新居中。

检查器只在打开状态显示，点击顶部栏图标打开、点击 `×` 关闭。检查器列宽度通过相对 CSS 约束（`clamp()`、`rem`、`vw`）适应可用空间，而不是按截图像素评判。主会话内容与 Composer 共用同一横向宽度规则。

小于桌面断点时，检查器列不参与布局，检查器改为全屏覆盖层。

## 工具审批策略

Composer 左下角使用 `Hand + 默认权限 + ChevronDown` 的圆角按钮。点击后由 Radix DropdownMenu 在 Composer 上方显示两项：

1. `默认权限`：当前项显示勾选。
2. `自动批准`：使用琥珀图标与文字表达高风险策略。

菜单不展示额外说明。选择后调用已有全局 `auto_approve_tools` API；不修改安全预检和 ToolExecutor 的二次检查。

## 活动与审批

活动簇只读取真实 TaskEvent。默认是一条低对比度、贴近背景的状态流：运行时显示最近动作，终态显示耗时和工具数量；点击才展开时间线。

等待审批时，活动簇下方显示大圆角琥珀审批面板：工具名为主要信息，参数以受限高度的等宽预览呈现。`拒绝` 是低强调圆角按钮，`允许一次` 是琥珀主按钮。不得展示模型 reasoning 或新增事件、存储。

## Composer 与形状

Composer 参考 DeepSeek 的输入优先布局：输入面与底部控制面分层，边框细、默认阴影弱、聚焦时使用操作蓝描边。发送使用带 Tooltip 的圆形图标按钮；运行中在相同槽位显示明确的 Stop 操作。

图标按钮、权限菜单、审批面板、输入框、检查器指标和对话框采用统一大圆角规则：控制件 14px，面板 18px，圆形图标按钮 999px。仅菜单、对话框和 Composer 允许低透明阴影；普通信息通过留白和边框分组。

## 验收

1. 在同一视口下，关闭检查器时消息列与 Composer 在完整主工作区居中；打开时主会话容器左边界不动、右侧收缩，消息列与 Composer 在收缩后的区域内居中且等宽；不以某张截图的绝对像素位置作为验收标准。
2. 权限按钮可键盘操作，菜单有 `menuitemradio` 语义；不显示冗余说明。
3. 活动簇和审批仅使用真实事件，审批操作不影响既有 Tool Permission 流程。
4. 发送、Stop、审批、菜单、检查器在深浅主题、缩放与窄屏下均不溢出。
5. 通过前端构建、状态测试、`pytest -q`、`git diff --check`；具备 Chromium 时补充 Playwright 截图。
