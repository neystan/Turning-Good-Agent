# Phase 7 Web Proactive Workbench Implementation Plan

> **历史计划，非当前事实依据。** 其中的跨进程主动所有权 Lease 和 loopback Bridge 已由单一 Gateway 取代；当前实现以 `docs/phases/2026-06-15-phase-6-web-observability.md`、`docs/phases/2026-06-15-phase-7-proactive-memory.md` 和 `docs/phases/2026-06-15-phase-8-im-channel-adapters.md` 为准。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 Phase 7 的 Cron、Breakbeat、长期记忆/Dream、Skill Draft 和 Incident 状态接入 Web，提供只读/确定性卡片墙、实时运行投影和不污染聊天的主动通知。

**Architecture:** Web 复用当前唯一 `AgentRuntime` 和 `RuntimeSupervisor`，通过一个跨进程所有权租约保证同一 `data_dir` 只有一个主动 Scheduler。领域读模型把持久化 `data` 与内存 `runtime` 分离；Web REST 返回完整领域快照，App 级 `/ws/proactive` 推送初始全量快照、后续领域快照和瞬时 notice。本机事件桥只转发快照/运行时/notice，不创建第二个 Runtime、不持久化运行时状态、不消费 `pending_deliveries.json`。

**Tech Stack:** Python 3.11、FastAPI、asyncio、现有 `AgentRuntime`/`ProactiveService`、React 18、TypeScript、Vite、Playwright、pytest。

## Global Constraints

- 保持单一 `AgentRuntime`、单一主动服务所有者；同一 `<data_dir>` 不得启动第二套 Scheduler。
- 六个主动状态文件继续是严格校验的 `.json` 快照；Web 不展示、不消费、不写入 `pending_deliveries.json`。
- 后台主动结果不进入聊天流、`messages.jsonl`、会话 WebSocket 或新的通知历史文件。
- 所有 Web 写操作是确定性 REST 控制操作，不经过 LLM、AgentLoop 或 Tool approval；前端二次确认，后端复核并加领域锁。
- `proactive_revision` 独立于 Runtime 配置 revision；快照必须同时提供持久化 `data` 和内存 `runtime`。
- 页面使用始终完整展开的卡片；长内容自然增高，由统一页面滚动承载，不使用折叠、详情弹层或“查看更多”。
- Web 通知只使用当前 App 内存中的不自动消失 Toast；同屏最多三条，浏览器关闭/刷新后不补播，不申请系统通知权限。
- 不展示模型 reasoning、思维链、单次 token 明细或后台 Tool 调用内容。
