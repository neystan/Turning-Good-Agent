# Phase 7.2 Proactive Simplification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Phase 7.1 proactive implementation with six minimal JSON snapshots, safe positive Tool allowlists, and simplified Cron/Breakbeat/Dream/Skill behavior.

**Architecture:** Each proactive capability owns one atomic JSON snapshot and its aggregate usage. `ProactiveExecutor` remains the single background LLM boundary, but receives an explicit allowed Tool set instead of writing execution audits. Cron, review capabilities, delivery, and incidents use those snapshots directly; no proactive JSONL remains.

**Tech Stack:** Python 3.12, asyncio, dataclasses, JSON, pytest, Docker Compose development backend.

## Global Constraints

- Work directly on `main`; the user explicitly requested no branches.
- Never stage or push files under `docs/`; plans and specifications remain local only.
- Before production code, add a focused failing pytest and observe its expected failure.
- Delete obsolete Phase 7.1 code and tests instead of retaining compatibility branches.
- On first Phase 7.2 startup, delete only the ten named old files under `<data_dir>/proactive/`; never delete `memory/USER.md`, `memory/SOUL.md`, unknown files, or directories.
- Keep `ProactiveService`, `ProactiveExecutor`, `ProactiveStore`, `ProactiveManager`, `ToolPermissionHook`, SessionStore JSONL, `complete_breakbeat`, and Incident history.
- Run focused tests after every task; run the full suite, compileall, CLI smoke, and `git diff --check` before the final code commit.
